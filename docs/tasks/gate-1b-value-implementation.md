## 0. 一句话 → 四个能力

| 主张词 | 能力定义 | 对应产品形态 | 技术落点 |
|---|---|---|---|
| **算清楚** | 口径透明：每个数字怎么算的，公式在单元格里可见可读 | 「业财利润公式」sheet = 口径表（每个减项一行：中文标签 + 活公式 + 数值 + 来源） | `finance-run.ts` + `calculate` |
| **改得动** | 假设驱动：改参数单元格 → 全表联动重算（含自然语言改参数） | 「假设参数」sheet 扩为 12 参数；口径表所有减项**引用参数格** | `write-inputs.ts` + `ensureAssumeSheet` |
| **能复核** | 审计留痕 → 把关：假设快照 + 匹配率标红 + 结果可下钻 | `_pack_audit` 行含假设快照与匹配率；<90% 显红「净利为近似口径」 | `pack-audit.ts` + 编排层 |
| **说清楚** | AI 人话结论：结果顶部一段话，答「怎么算的/哪些是近似/哪些 SKU 有风险」 | 跑完返回三段式结论（口径 / 近似项 / 风险 SKU） | `finance-run.ts` 返回值 + 前端 |

> **关键设计约束（架构铁律）**：AI 结论只能读 **summary 数字**（recon.counts、SUMIFS 结果、审计行、参数快照），
> **表体从不进模型上下文**。解释层不读源表行，否则破坏「表体不进模型」的安全边界。

## 1. 能力 A：活公式口径表（算清楚 + 改得动，两者是一张表的两面）

**老板视角**：打开「业财利润公式」sheet，不是一串看不懂的数字，而是——
每行一个减项：`收入 / COGS / 佣金 / FBA配送 / 仓储均摊 / 广告 / 退款 / = 净利`，
每行左侧中文标签、中间**引用单元格的活公式**（点进去能看到公式）、右侧数值、末尾「来源」列（参数 / 源表 / 公式）。

### 1.1 假设参数区扩为完整字段（现状：只有 B2–B4 三个）

`ensureAssumeSheet` 目前只写 3 个参数（USD汇率 7.2 / 广告占比 8% / 退款率 3%），
且**与 `profit_formula.md` §四 的 12 字段清单不一致**（缺佣金率、FBA 基础、燃油附加、仓储均摊、支付手续费、目标净利率、COGS 映射…）。
按 §四 清单补齐参数区（含默认值取 `profit_formula.md` 区间中值，**先解决 G6 费率单一真相**）：

| 参数（示例） | 单元格 | 默认 |
|---|---|---|
| USD汇率 | B2 | 7.2 |
| 佣金率 | B3 | 15% |
| 退款率 | B4 | 8% |
| FBA 基础费 | B5 | 3.22 |
| 燃油附加 | B6 | 3.5% |
| 仓储均摊 | B7 | 1.50 |
| 支付手续费率 | B8 | 2.5% |
| 目标净利率 | B9 | 10% |
| COGS 映射表 | 独立区域 | 空（可填） |

### 1.2 口径表生成（替换现在的单行 SUMIFS）

现状 `finance-run.ts:148` 只做 `calculate_table({op:"sumifs", valueColumn:"left_item_price"})` —— **只有收入列，没有减项，公式不引用参数格**。
改为生成口径表（同 sheet，逐行）：

```
行1 收入        =SUMIFS(recon[item_price], recon[sku], A5)              ← 源表活公式
行2 COGS        =SUMIFS(cogs_map[单价], cogs_map[sku], A5)*数量          ← 引用 COGS 映射表（空则标黄不阻断）
行3 佣金        =行1*$B$3                                                 ← 引用参数格
行4 FBA配送     =数量*$B$5*(1+$B$6)                                      ← 引用参数格
行5 仓储均摊    =数量*$B$7*0.05(按体积系数，可配置)                        ← 引用参数格
行6 广告        =SUMIFS(recon[spend], recon[sku], A5)                    ← 源表活公式
行7 退款        =退款行数*行1毛利率*$B$4                                  ← 引用参数格；有 refund_amount 用实值
行8 净利        =行1-行2-行3-行4-行5-行6-行7
```

**验收标准（能改得动）**：
- [ ] 改 B4（退款率 8%→12%）→ 净利列**自动重算**（不用重跑流程，Excel 原生联动）
- [ ] 改 B3（佣金率 15%→17%）→ 佣金列、净利列联动
- [ ] 每个减项单元格点开**能看到公式**（不是硬编码数值）
- [ ] COGS 为空时该行标黄、净利仍可算（不阻断）
- [ ] 退款行：`is_refund=true` 不静默加进收入基数（G3 落地）

> 技术注：公式写格走**核心算子通道**（`calculate` 等已有能力），Pack 层只负责组装公式字符串；
> 若现有算子不支持「跨表 SUMIFS 引用」或「条件格式标色」，在 Pack 层新增小工具，**核心算子仍不动**（边界见 §6）。

## 2. 能力 B：把关升级（能复核）

**老板视角**：对完账，结果页能一眼看到——「这份账匹配率 87%，**净利是近似口径**」红字；
审计行里存着「跑这批数时用的假设：汇率 7.2 / 佣金 15% / 退款率 8%」——将来对账有争议，翻得出当时怎么算的。

**现状**：`_pack_audit` 已有 sourceHash / matched / left_only / right_only / conflict / reviewPending（留痕 ✅），
但缺**假设快照**和**匹配率阈值标色**（留痕 ≠ 把关）。

### 2.1 假设快照入审计

`appendPackAudit` 增参：`assumptionSnapshot`（跑时 B2–B9 的值 JSON 字符串）+ `matchRate`（matched/total）。
`finance-run.ts` 在 appendPackAudit 前从假设参数区读取当前值组装快照。

### 2.2 匹配率把关

- `matchRate = matched / total`（`finance-run.ts` 已算 total，直接复用）
- 阈值：**<90% → 结果页顶部红字「净利为近似口径，匹配率 X%，请复核 __review 行」**；≥90% 正常提示
- 落到 `_pack_audit.note` + 返回文案（前端展示）

### 2.3 结果可下钻

- 口径表/透视每个 SKU 行 → 能跳到「业财对账结果」对应行（reconcile 已输出，`__review=需复核` 行已存在）
- 验收：点 SKU 净利行，能看到它由哪几行订单/广告组成（依赖现有 sheet 跳转能力，无则 Pack 层加「下钻汇总行」）

**验收标准**：
- [ ] 审计行含假设快照（跑时参数值，JSON）
- [ ] 匹配率 <90% → 返回文案 + 结果页显红警示
- [ ] 退款负金额不静默进汇总（与 A 共用验收）

## 3. 能力 C：AI 人话结论（说清楚）

**老板视角**：跑完不是甩 7 行步骤日志，而是**一段人话**：

> 「这个月订单 $52,000、广告 $4,200。按你给的参数（汇率 7.2、佣金 15%、退款率 8%）：
> 净利合计约 ¥XX 万，**净利率 9.8%，低于你设的 10% 目标**。
> 3 个 SKU 亏钱（A/B/C），主因是广告占比高（TACOS 22%）+ 退款率超均值的服装类目。
> 注意：归因有 ≤7 天偏移、退款是预估，**净利是近似口径**；匹配率 94%，对账可信。」

**形态**：三段式结论——① 怎么算的（口径一句话）② 哪些是近似（退款预估/归因偏移/匹配率）③ 哪些 SKU 有风险（净利≤0、净利率<目标、TACOS>15%）。

**技术落点**：`finance-run.ts` 返回字符串重构（现在只是步骤清单）：
- 第①段：固定模板 + 参数快照
- 第②段：来自审计行（matchRate、reviewPending、归因 note）
- 第③段：来自口径表/透视的 **summary 聚合**（SKU 级净利≤0 的列表，由 `calculate` 输出，**不进模型上下文**）

**验收标准**：
- [ ] 跑完返回含三段式人话结论，能直接答「哪些 SKU 亏钱、为什么、数可不可信」
- [ ] 结论中所有数字可追溯到口径表单元格（不编造）
- [ ] 全程表体未进模型上下文（审计可查）

## 4. 实施顺序（依赖关系：A → B → C）

| 步 | 任务 | 依赖 | 对应能力 | 验收 |
|---|---|---|---|---|
| 1 | **活公式口径表**：参数区扩 12 字段（顺带 G6 单一真相）+ 口径表生成替换单行 SUMIFS + 退款剔除 | — | 算清楚+改得动 | §1.2 验收清单 |
| 2 | **把关升级**：假设快照 + 匹配率阈值标红 | 步 1（参数区完整） | 能复核 | §2 验收清单 |

> 步 4 是「改得动」的 AI 增量版本——Excel 原生联动是地基，自然语言改参数是上面的体验层。

## 6. 边界与依赖

- **不动**：`reconcile-core.ts` 等核心算子、写格单通道、`profit_formula.md` 口径定义（已是权威）、审计机制本身
- **动**：`finance-run.ts`（编排层：参数区扩展、口径表生成、返回重构）、`write-inputs.ts` 调用参数、`pack-audit.ts`（增参，向后兼容）、Pack 内公式/标色小工具
- **依赖确认项（执行器开工前查）**：
  - 现有 `calculate` 算子是否支持**跨表 SUMIFS 引用 + 输出公式字符串**（非数值）——不支持则 Pack 层加「公式写格」小工具
  - 现有 sheet 能力是否支持**条件格式标色**（<90% 红字、COGS 空标黄）——不支持则用「警示列文本 + 返回文案」替代（降级方案，不阻塞验收）
  - `write-inputs.ts` 是否支持写「带 = 前缀的公式」——不支持则 Pack 层组装
