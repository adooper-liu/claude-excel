# 任务：对账模型参数化（粒度 / 归因 / 币种 + 优先级收敛）

> Claude Code × Cursor 唯一交接载体。聊天只传文件名 + 分支名。

- **分支**：`feat/reconcile-model`
- **状态**：`design`
- **主责（当前阶段）**：Claude Code（design）→ Cursor（coding）

## 目标

把「对账」从写死的 `sku+date` 精确匹配，改造成**三参数（粒度 / 归因 / 币种）驱动**的通用对账。参数由「显式指定 → AI 推断确认 → SKILL 默认」三级优先级收敛，**每次运行收敛到唯一一份口径配置**，写进 `_pack_audit` 可追溯。

## 边界 / 不做

- **AI 只列候选，绝不直接决定并执行**——这是铁律，防止 AI 幻觉。
- **写格仍唯一走核心算子**：聚合/对账走现有算子扩展，不新增执行器、不写 Python 脚本。
- **列映射仍留在 Pack（L3）**，核心不认识平台列名。
- **不做**：精确归因模型（7 天窗口摊到成交）、按日汇率表、ERP API 直连——归因留 Phase 2。

## 三参数（每个独立决策）

| 参数 | 选项 | 默认（待你拍板） |
|---|---|---|
| **粒度**（聚合键） | SKU / SKU×日 / SKU×月 / SKU×站点 | **SKU×月**（广告报表多为月汇总，订单行级） |
| **归因口径**（广告花费归到哪） | 点击日归集（不归因）/ 成交日归因（精确） | **点击日归集**（先做对，精确归因 Phase 2） |
| **币种归一** | 固定汇率 / 按日汇率表 / 不归一（分币种看） | **固定汇率**（参数 sheet 填） |

**关键**：三参数是**正交**的，各自独立决策，不是整体三选一。用户可能指定了粒度、没指定归因和币种——则粒度走 P0，归因/币种走 P1/P2。

## 三路径优先级组合策略（核心）

> 三条路径不是并列，是**级联 fallback**，最终收敛到唯一口径。

| 优先级 | 路径 | 触发条件 | 动作 |
|---|---|---|---|
| **P0** | 显式指定 | 用户明确说出某参数（「按 SKU 对」「按点击日归集」） | 直接采用，覆盖下面所有 |
| **P1** | AI 推断 + 确认 | 某参数用户没指定 | 提取两表样本 → LLM 列 2–3 个候选（默认值来自 P2 的 SKILL 口径）→ 用户确认或改 |
| **P2** | SKILL 默认口径 | 用户既不指定、也不确认（直接跑） | 用 SKILL 默认值，`_pack_audit` 标注「默认口径」 |

**每个参数独立走 P0→P1→P2**。收敛结果 = 一份「口径配置」`{粒度, 归因, 币种}`，每次运行唯一，写进 `_pack_audit`：

```
_pack_audit 追加列：粒度=SKU×月, 归因=点击日归集, 币种=固定汇率7.2, 口径来源=用户指定/推断确认/默认
```

「口径来源」这一列让结果可追溯——用户能看出这次是用他指定的口径算的，还是默认口径兜底的。

## AI 推断的候选生成（P1 细节）

- 用 `inspect_table` 取两表表头 + 前 20 行样本 + 列类型（表体不进对话）。
- LLM 推断：哪个列是 SKU、哪个是日期、日期粒度日/月、两表能否在某键对齐。
- **红线**：只列候选，展示「我推断按 SKU×月，因为广告报表日期是月份粒度。对吗？」→ 用户确认/修改后才执行。
- 候选的排序与默认值来自 P2 的 SKILL 口径（推断有先验，不凭空猜）。

## 落地改动（扩参数，不新增机制）

1. **聚合能力**：现有 `reconcile_tables` 只做精确键匹配，没有「先 groupby 到目标粒度再对比」。优先扩 `reshape_table` 或 `calculate_table` 加 `groupby` 聚合；不新增算子、不写 Python。
2. **SKILL 口径说明**：`knowledge/reconcile-caliber.md`（或并入 profit_formula.md）写清三参数选项 + 默认值 + 常见场景（什么场景用日粒度、什么用月）。
3. **recipe 编排**：`finance-reconciliation/SKILL.md` 加「口径确认」步骤——先问用户三参数，不明确则走 P1 推断，仍无则 P2 默认。
4. **审计**：`pack-audit.ts` 追加「粒度/归因/币种/口径来源」列。
