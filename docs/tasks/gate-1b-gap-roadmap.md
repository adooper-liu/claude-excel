# Gate 1b 缺口路线图：7 项缺口怎么办

> 状态：方案（Claude Code 只读评审，供决策对齐）
> 日期：2026-08-24
> 依据：`docs/gate-1b-external-narrative.md` §4 诚实清单 + `gate-1b-self-critique.md` 定位修正
> 一句话：**不是所有缺口都该自己补。做了有没有差异化、该不该自己做，是两道题。**

---

## 0. 判断框架

诚实清单里 7 项缺口，按"**做了构成差异化吗** + **该我们自己碰吗**"两问，分三类：

| 类 | 判断 | 处置原则 |
|---|---|---|
| **A 该做，差异化主战场** | ERP 给不了 + Excel 主场 + AI 增量明显 | 现在做 |
| **B 该碰，轻量补、不硬做** | 小修就能提升精度，但不追求 ERP 级 | 顺手补，诚实标注边界 |
| **C 不该自己做** | 需要基础设施（API 自动同步/复杂引擎）我们没有，正面撞 ERP 拳头 | 承认边界，走"中间路线"而非硬碰 |

---

## 1. 逐条判断

### 现金流管理 — C 类，不该自己做

卖家最痛，但 Claude Excel 没有 API 自动同步库存/采购/回款数据的基础设施。**现金流管理**需要实时拉 ERP + 银行流水，正面撞 ERP/财务系统，打不过。

**中间路线**：碰"现金流敏感性假设分析"（如果回款延迟 7 天、补货周期拉长 10 天会怎样），不碰"现金流管理"本身。前者是 H3 的延伸（假设分析），后者是系统级能力。

### 收款工具层 — B 类，一个格子的事

资金流模型止于"亚马逊结算"，Payoneer/连连等收款工具费差 0.25%–1%。

**怎么办**：修正 B8 支付手续费率默认值（当前 2.5% 疑似偏高，收款工具实际 0.25%–1%，连连/PingPong）。这是参数区一个格子，低成本。`profit_formula.md` §一 已写"2%–3% 跨境收款商惯例"，与实际区间有出入——**统一为单一真相**：默认值改 1%，区间标注 0.25%–3%。

### 结算×银行对账 — A 类，技术验证主菜（H2）

做了订单×广告，没做结算报告×银行流水。

**怎么办**：这是 **Settlement feed（H2）** 的核心——定位为**技术验证**（证明管道接得住平台结算单这种结构最复杂的数据源），不是商业卖点。结算单是亚马逊 FBA 卖家的"现金实现锚点"，对账价值真实，但对外不吹"业财闭环"。在 H1 净利闭环（已完成）+ H3 敏感性分析之后做。

### 批次成本核算（FIFO/加权平均）— C 类，不做

同一 SKU 不同批次采购价不同时算不准。

**怎么办**：不做 ERP 级 FIFO/加权引擎——做了也不构成差异化，且引入复杂库存逻辑。**COGS 当用户填的固定值，诚实标注"批次成本未核算，COGS 为用户输入的均值"**。诚实标注比硬塞不准的引擎更值钱。

### 固定成本分摊 — B 类，轻量补 + 诚实标注

只有变动成本（佣金、FBA、广告），没有仓租/人工/ERP 订阅的分摊。

**怎么办**：可选加一个"固定成本月度摊销"参数格（用户自填月度固定成本总额，按 SKU 收入占比分摊），不追求精度。**关键：口径表标题/审计行明确标注"本表为边际贡献口径，未含固定成本分摊"**——把"这是边际贡献不是净利润"说清楚，是产品诚实的一部分。

### 多平台（TikTok Shop / Walmart / 独立站）— B 类，架构已留路，缺 recipe

只覆盖亚马逊。

**怎么办**：**架构上 connector 可替换，已经为多平台留好了路**（`csv_local` 与未来 `erp_jijia/erp_lingxing` 同接口，recipe 只认 canonical 列）。缺的是 recipe（每个平台一个配置）。这是规模问题不是架构问题——按真实用户需求驱动，有 TikTok Shop 卖家来就加一个 recipe，不来就不做。不预先造。

### ERP 数据打通 — C 类，不碰 OAuth，走"导出补充"路线

从 CSV 开始，不跟 ERP 对接。

**怎么办**：**不碰 ERP OAuth/API 自动同步**（正面打没赢面，ERP 数据源本来在它手里，走 API 自动同步我们做不过）。中间路线：支持"用户从 ERP 导出 CSV 喂进来"的补充分析场景——承认"不能替代 ERP 的自动同步，但能在 ERP 数据不够用的时候做补充分析"（如敏感性分析、口径透明）。这是对外叙事里已经写明的定位。

## 2. 优先级排序

| 序 | 事项 | 类 | 服务于 | 量级 |
|---|---|---|---|---|
| 1 | **H3 敏感性分析** | A | 商业验证主战场 | 主体（SKILL.md 扩展批量矩阵 + 自然语言改参数） |
| 2 | B8 参数修正 + 固定成本诚实标注 | B | H1 精度 + 信任度 | 小（参数区 + 标注） |
| 3 | H2 Settlement feed | A | 技术验证 | 中（新 connector feed + 对账扩展） |
| 4 | 多平台 recipe | B | 规模扩展 | 按需（每个平台一个 recipe） |
| 5 | 现金流/批次/ERP 打通 | C | 不做 | 诚实标注边界 |

---

## 3. 一句话主张

> **诚实标注"没做什么"本身就是产品价值**——把"这是边际贡献不是净利润""COGS 是用户输入的均值""不碰现金流管理"说清楚，比硬塞一个不准的固定成本分摊或自建一个打不过 ERP 的现金流引擎更值钱。
>
> 缺口不是"欠的债"，是"该不该自己做"的选择题。该做的（H2/H3）做，不该做的（现金流/批次/ERP OAuth）诚实承认边界，走中间路线。
