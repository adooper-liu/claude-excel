# 可靠性批判：1–8 层论证（反方意见，下一轮修复开始时必须重读）

> 状态：反方意见存档 · 2026-08-18
> 消费者：任何写格/路由/状态相关的改动评审前必读。本文不是结论，是防止"用行为补丁装饰架构"的护栏。
> 相关：[architecture-llm-first.md](architecture-llm-first.md)（落地形态）、`docs/coordination.md`。

## 论证主线

P(错) 有地板（语义歧义不可约）→ 压代价 → 代价拆成 可发现×可逆 → 可发现需要 ground truth → ground truth 只在用户手里 → 用户站在提交门 → 事故说明行为规则不够，要结构隔离 → AI 不可靠是本质，系统在它周围可靠。

## 第 1–5 层（原始论证）

1. **期望损失不等式**：期望损失 = P(错) × 代价(错)。P(错) 有不可约地板，代价可趋近于零 → 压你能控制的项。
2. **可发现性地板**：错误静默时，可逆也没用。需要对照物（ground truth）。
3. **ground truth 只在用户手里** → 用户必须站在提交门：AI 提议 → 用户确认 → 执行，而不是 AI 执行 → 用户事后检查。
4. **结构隔离 > 行为规则**：flatten 改值、路由劫持、向量失效——都是结构允许了错误（共享代码路径 / 前置层可拦截 / 无版本约束）。行为规则（prompt/guard/checklist）的可靠性有天花板（执行者会错）；结构隔离让错误物理上不可能。
5. **底层**：别想让 AI 更可靠，让系统在不可靠的 AI 周围可靠。四支柱：写面最小化 / 高代价不自治 / fail-visible / 派生带版本。最深一层：自动化是期望损失不等式问题，高代价动作默认不自治。

## 第 6–8 层（反方追加）

6. **用户提交门也是另一个 P(错)，且随使用衰减**：确认注意力预算有限，前 10 次认真看、第 100 次盲点。可逆代价被低估（定位谁受影响 + 回滚传播，而血缘理解正是语义歧义所在）。"用户站提交门"只对交互场景成立，批量/无人值守场景要么回到自治+高 P(错)，要么审计门（发现延迟又把可发现性打回原形）。
7. **错误有两种，结构只防 A 类**：A 类值错误（可检测，schema/类型/范围约束能抓）vs B 类意图错误（任何解释都"合法"，只有用户知道要哪种，不可检测）。本系统三个事故全是 B 类高发。对策不是结构隔离，是**歧义前置**：执行前把"我理解的 X/Y"显式化给用户选，作用在意图层而非执行层。
8. **"可靠性的剧场"**：衡量"故障被捕获"≠"系统做对"。fail-visible 久了变噪音。底层结论是决策理论（每个操作单独填决策表），不是架构支柱——把它写进 docs 当约束 = 用经济学期刊指导施工队。

## 替换表（诚实版）

| 原支柱 | 实际 | 该替换成 |
|---|---|---|
| 写面最小化 | 对的，但只防 A 类 | 写面最小化 + 歧义前置（B 类） |
| 高代价不自治 | 只对交互场景成立 | 高代价 → 提交门（在线）/ 审计门（离线），建模确认衰减 |
| fail-visible | 短期对、长期变噪音 | 可见 + 分级 + 衰减 + 静默期 |
| 派生带版本 | 唯一真结构修复 | 保留，版本来自 schema 迁移，非写方自报 |

## 一针见血

- 唯一真结构修复：EMBED_VERSION（让失效从静默变可检测）。
- 其余行为补丁：给行为补丁群披上架构外衣 = 剧场。
- 判定该不该留正则/该不该自治，依据期望损失不等式，不是架构美学。

## 使用方式

新增写算子 / 改路由 / 改状态格式时，过一遍：这是 A 类还是 B 类处理？这笔是真结构还是剧场？提交门/歧义前置做没做？确认衰减建模没有？
