## Gate 1b 缺口路线图（docs/tasks/gate-1b-gap-roadmap.md，新落盘）

- 用户问「Gate 1b 没有做的部分怎么办」，基于前几轮上下文（诚实清单 7 项缺口 + 批判定位修正）直接给策略判断，未改代码。
- 核心框架：7 项缺口按「做了构成差异化吗 + 该我们自己碰吗」两问分三类——A 该做（H2 结算 feed 技术验证 / H3 敏感性分析主战场）、B 轻量补不硬做（收款工具层 B8 参数修正、固定成本诚实标注、多平台 recipe 按需）、C 不该自己做（现金流管理/批次 FIFO/ERP OAuth，走中间路线不硬碰）。
- 关键判断：诚实标注「没做什么」本身就是产品价值——边际贡献不是净利润、COGS 是用户输入均值、不碰现金流管理，比硬塞不准的引擎更值钱。缺口不是欠的债，是「该不该自己做」的选择题。
- 优先级：① H3 敏感性分析 → ② B8 参数修正+固定成本诚实标注 → ③ H2 Settlement feed → ④ 多平台 recipe 按需 → ⑤ C 类不做诚实标注。

## Pack 能力天花板分析（docs/tasks/pack-capability-ceiling.md，新落盘）

- 用户问「Pack 行业包能否在 excel 插件界面完成引导用户与新建、安装，决定了 Pack 的能力天花板」。
- 读了 PackMenu.tsx（UI）、user_packs_store.py（后端安装管线）、App.tsx（集成）、builtin-skills.ts（/skill-creator）、user-skills.ts（import/export）。
- 核心发现：L0-L2+L4 已落地（安装/卸载/导入/导出/LLM 生成 Skill），**L3 是关键缺口**——用户不能在 UI 里创建完整 Pack。
- 缺口不大：/skill-creator 已做 80%（生成 SKILL.md），差的是 pack.json 生成 + 知识文件上传 + 打包安装闭环。
- 推荐路线 A（对话式 Pack Builder）：扩展 /skill-creator 输出 pack.json + 调 create-pack API，PackMenu 只加一个按钮。
- L3 通了 → L4 已通 = 用户自造 Pack → 导出 → 分享 → import 最小闭环，不需要云端市场。
- L5（市场分发）是商业决策不是技术决策，先有 L3+L4 的自造自分享数据再决定。
